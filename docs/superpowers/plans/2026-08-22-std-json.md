# `std/json` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `std/json` — a JSON parser, serialiser and codec traits — completing Phase 2 position 11, taken before position 10.

**Architecture:** `JsonValue` is a recursive sum type exactly as `nova-spec/20-STDLIB.md` §7 declares it. `stringify` is total and needs no error machinery. `parse` is a recursive-descent walk over a **poisoned state record**, because Nova has no `?` operator. One new intrinsic converts decimal text to `Float`; everything else, including `\uXXXX` decoding, uses primitives that already ship.

**Tech Stack:** Nova (`std/json/lib.nova`, `std/collections/lib.nova`), Rust for one intrinsic across five crates.

**Spec:** `docs/superpowers/specs/2026-08-22-std-json-design.md`

### Measured language facts — rely on these, do not re-derive

All verified at `8f57975`:

- **No `?` operator** — `error[E0900]`. This is why the parser carries its error instead of returning `Result` everywhere.
- **No turbofish** — a type parameter appearing only in a return position needs an annotated `let` at the call site.
- **Recursive sum types work**, both through an array (`| Node([Tree])`) and through a generic record (`| Obj(Map<String, Node>)`).
- **Variant names may shadow builtin type names** — `Bool(Bool)` and `String(String)` compile, and `match` arms bind them unqualified.
- **`Self` in trait return position** and **receiverless trait functions** both work. An `impl` writes the **concrete type**, not `Self`: `impl Default for Int { fn default() -> Int { 0 } }` (`std/core/lib.nova:540`).
- **`char_to_int` is `STD_ONLY`** — usable inside `std/json`, `error[E0001]` from user code. Fixtures must exercise digits through the public API.
- **No Int → `Char`** and **no string → number** conversion exists.
- **No `loop` keyword.** `match` arms do not bind `mut` — rebind inside the arm. `mut self` receivers are required at field-assignment and method-call sites (`E0060`).
- `String` offers `chars() -> [Char]`, `char_at(i) -> Option<Char>`, `slice(start, end)`, `len()`, `split`, `trim`, `index_of`. `Option` has `unwrap`, `is_some`, `is_none`, `map`, `unwrap_or`.
- **`Map` has exactly seven public methods** — `new`, `len`, `is_empty`, `insert`, `get`, `contains_key`, `remove`. **It cannot be iterated.** Task 1 fixes that.

Add to `impl<K: Hash + Eq, V> Map<K, V>`, after `remove`:

```nova
    // The live keys, in table order. `state[j]` is 1 for occupied, 2 for a
    // tombstone and 0 for empty, so this is the same walk `grow` already does
    // to find the entries worth reinserting.
    //
    // The `[fill; n]` seed is forced rather than stylistic: allocating a `[K]`
    // needs a `K` in hand and Nova has no null, so the first live key seeds the
    // array and the collecting walk then overwrites every slot. `Vec::push`
    // grows by the same manoeuvre.
    //
    // Table order is deliberately NOT insertion order, and no caller should
    // assume it is: a `grow` reinserts every entry and can reorder them.
    pub fn keys(self) -> [K] {
        if self.len == 0 { return [] }
        let cap = self.state.len()
        let mut seed = 0
        let mut i = 0
        while i < cap {
            if self.state[i] == 1 { seed = i; i = cap } else { i = i + 1 }
        }
        let mut out = [self.keys[seed]; self.len]
        let mut w = 0
        let mut j = 0
        while j < cap {
            if self.state[j] == 1 {
                out[w] = self.keys[j]
                w = w + 1
            }
            j = j + 1
        }
        out
    }
```

- [ ] **Step 2: Write `std/json/lib.nova`'s type and `stringify`**

```nova
// Nova standard library -- JSON.
//
// `nova-spec/20-STDLIB.md` section 7's type declaration compiles verbatim,
// including the variant names that shadow builtin type names. Measured, not
// assumed: `Bool(Bool)` and `String(String)` are accepted and `match` binds
// them unqualified.

pub type JsonValue =
    | Null
    | Bool(Bool)
    | Number(Float)
    | String(String)
    | Array([JsonValue])
    | Object(Map<String, JsonValue>)

// `at` is a character index into the input, not a byte offset -- the parser
// walks `[Char]`.
pub record JsonError { msg: String, at: Int }

// Render `v` as JSON text. Total: there is no input this cannot render.
pub fn stringify(v: JsonValue) -> String {
    match v {
        Null => "null"
        Bool(b) => if b { "true" } else { "false" }
        Number(n) => number_to_json(n)
        String(s) => quote(s)
        Array(xs) => {
            let mut out = "["
            let mut i = 0
            while i < xs.len() {
                if i > 0 { out = "${out}," }
                out = "${out}${stringify(xs[i])}"
                i = i + 1
            }
            "${out}]"
        }
        Object(m) => {
            let ks = m.keys()
            let mut out = "{"
            let mut i = 0
            while i < ks.len() {
                if i > 0 { out = "${out}," }
                match m.get(ks[i]) {
                    Some(val) => out = "${out}${quote(ks[i])}:${stringify(val)}"
                    None => out = out
                }
                i = i + 1
            }
            "${out}}"
        }
    }
}

// JSON has no NaN and no infinity, so a non-finite number cannot be rendered.
// This emits `null` instead, which is what most codecs do and which keeps
// `stringify` total and its output always valid JSON. It is DELIBERATELY LOSSY:
// a round trip through a non-finite number does not preserve it.
//
// `n - n != 0.0` is the finiteness test. For any finite `n` the difference is
// exactly zero; for either infinity it is NaN, and for NaN it is NaN, and NaN
// compares unequal to everything including itself. This avoids needing an
// `is_nan` the standard library does not have.
fn number_to_json(n: Float) -> String {
    if n - n != 0.0 { "null" } else { "${n}" }
}
```

- [ ] **Step 3: Write `quote`, the output escaper**

RFC 8259 requires `"` and `\` escaped, and every character below `0x20`. Everything else passes through, including non-ASCII, because the output is UTF-8.

```nova
// Escape `s` as a JSON string literal, quotes included. `char_to_int` is how
// this reaches a character's scalar value -- it is `STD_ONLY`, which is why
// this helper lives here rather than in a fixture.
fn quote(s: String) -> String {
    let cs = s.chars()
    let mut out = "\""
    let mut i = 0
    while i < cs.len() {
        let c = cs[i]
        let code = char_to_int(c)
        if c == '"' {
            out = "${out}\\\""
        } else {
            if c == '\\' {
                out = "${out}\\\\"
            } else {
                if code < 32 {
                    out = "${out}${escape_control(code)}"
                } else {
                    out = "${out}${c}"
                }
            }
        }
        i = i + 1
    }
    "${out}\""
}
```

**`escape_control(code: Int) -> String`** returns `\n`, `\r`, `\t`, `\b`, `\f` for those five, and `\u00XX` with two lowercase hex digits otherwise. Write it with an explicit `if`/`else` chain and a two-character hex helper; there is no `loop` keyword and no formatting width primitive to lean on.

- [ ] **Step 4: Write the number scanner and the parser skeleton**

```nova
// The parser carries its failure instead of returning `Result` at every level.
// Nova has no `?` operator (measured: `error[E0900]`), so threading a `Result`
// through a recursive descent costs a `match` at every call site and buries the
// grammar in plumbing.
//
// `err` is set at most once: the FIRST failure wins, so a downstream symptom
// cannot overwrite the real cause. Every step that could read past the end
// checks `err` first and no-ops, returning `Null` -- after a failure the
// remaining walk is inert rather than wrong.
record P { cs: [Char], pos: Int, err: Option<JsonError> }
```

with `fail(mut self, m: String)` guarded by `if self.err.is_none()`, `at_end(self) -> Bool`, `peek(self) -> Char` returning a harmless sentinel past the end, `bump(mut self)`, and `skip_ws(mut self)` over space, tab, newline and carriage return only — **JSON permits no other whitespace**.

- [ ] **Step 1: Write the escape decoder**

`\uXXXX` cannot become a `Char` — **there is no Int → `Char` conversion anywhere.** The route, using only shipped primitives:

1. Four hex digits → an `Int` code point, via `char_to_int` on each digit.
2. If the value is a **high surrogate** (`0xD800`–`0xDBFF`), require a following `\u` low surrogate (`0xDC00`–`0xDFFF`) and combine:
   `0x10000 + (high - 0xD800) * 0x400 + (low - 0xDC00)`.
   An unpaired surrogate on either side is a `fail`.
3. Encode the code point to UTF-8 bytes in Nova — the four standard ranges.
4. `bytes_from_ints(ints)` then `Bytes::to_string()`, which returns `Option<String>`.

**Step 4's `Option` is the validation and is why no second intrinsic was added.** `to_string` checks UTF-8 and returns `None` rather than producing garbage, so a malformed code point becomes a `JsonError` for free. Note the runtime's own `nova_rt_char_to_str` does `char::from_u32(v).unwrap_or(REPLACEMENT_CHARACTER)` — it *silently substitutes* U+FFFD. Exposing that would have been strictly worse than this route.

The simple escapes `\" \\ \/ \b \f \n \r \t` are direct. A `\` followed by anything else is a `fail`, and so is an **unescaped character below `0x20`** inside a string — both required by RFC 8259.

- [ ] **Step 2: Write `parse_value` and `parse`**

`parse_value` dispatches on `peek()`: `n`→`null`, `t`/`f`→booleans (each spelling checked in full, not by first letter), `"`→string, `[`→array, `{`→object, `-` or a digit→`scan_number`, anything else→`fail`.

`parse` builds a `P`, skips whitespace, parses one value, skips whitespace, and **fails if anything remains** — trailing content is an error, not ignored. Then it inspects `err` once:

```nova
pub fn parse(s: String) -> Result<JsonValue, JsonError> {
    let mut p = P { cs: s.chars(), pos: 0, err: None }
    p.skip_ws()
    let v = p.parse_value()
    p.skip_ws()
    if !p.at_end() { p.fail("trailing content") }
    match p.err {
        Some(e) => Err(e)
        None => Ok(v)
    }
}
```

- [ ] **Step 3: The three fixtures**

`json_parse_strings.nova` — the simple escapes, a `A` giving `A`, a surrogate pair giving one astral character, an unpaired high surrogate rejected, a lone `\q` rejected, and a raw control character rejected.

`json_parse_values.nova` — `null`, both booleans, nesting, an empty array, an empty object, whitespace in every legal position, and rejections for a trailing comma, a missing colon, an unterminated string, unbalanced brackets, and trailing content.

**`json_round_trip.nova` is the load-bearing fixture.** Build a value using **every** variant — including an array nested inside an object, an escape, and a non-integral number — `stringify` it, `parse` that back, `stringify` again, and assert the two texts are equal. It is the only test that checks both directions against each other rather than against a golden the author chose. Note it cannot pin key order across a multi-key object, so use one key per object or compare a canonical form.
