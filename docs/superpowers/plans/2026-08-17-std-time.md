# `std/time` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Nova a monotonic clock and a duration type — `nova-spec/20-STDLIB.md` §9 minus its two async combinators — and move `sleep` off `std/task` onto a real `Duration`.

**Architecture:** `Instant` and `Duration` are ordinary Nova records over a private `Int` of nanoseconds, so every arithmetic operation is Nova code. The runtime contributes exactly one new intrinsic, a monotonic clock reading, because that is the only thing here Nova cannot express. The existing sleep parker is retyped from milliseconds to nanoseconds and renamed in the same change, because its type is unchanged by the retype and a rename is what makes a stale call site a compile error.

**Tech Stack:** Rust (nova-runtime, nova-resolver, nova-typeck, nova-mir), Nova (`std/time/lib.nova`), fixtures under `tests/runtime/`.

**Spec:** `docs/superpowers/specs/2026-08-17-std-time-design.md` (committed at `518d521`). Read it alongside this plan; the plan argues from it.

```rust
//! Monotonic clock readings for `std/time`.
//!
//! One origin and one intrinsic, deliberately. `Instant` and `Duration`
//! arithmetic is Nova code in `std/time/lib.nova` -- a subtraction does not
//! need to cross into Rust. This module exists only because a clock reading
//! is the one thing in §9 that Nova cannot express at all.

use std::sync::OnceLock;
use std::time::Instant;

/// The single process-monotonic origin every reading is relative to,
/// initialized on first read so no reading is ever negative.
///
/// **Shared on purpose.** `poll.rs`'s log rate limiter reads this same origin;
/// it used to own a second `OnceLock<Instant>` of its own (`log_epoch`). Two
/// independent origins that merely happen to agree is worse than one named for
/// what it is.
pub(crate) fn epoch() -> Instant {
    static EPOCH: OnceLock<Instant> = OnceLock::new();
    *EPOCH.get_or_init(Instant::now)
}

/// Nanoseconds since [`epoch`], saturating at `i64::MAX`.
///
/// **Saturates rather than wrapping.** `as_nanos` is `u128`, and a bare
/// `as i64` would wrap after roughly 292 years of process uptime. A wrapped
/// reading is negative, `std/time` computes `Duration`s from it by
/// subtraction, and `sleep` treats a non-positive duration as an immediate
/// wake -- so a wrap would turn a very long sleep into no sleep at all. A
/// clamp keeps a useless answer from becoming a wrong one.
#[no_mangle]
pub extern "C-unwind" fn nova_rt_time_now_nanos() -> i64 {
    i64::try_from(epoch().elapsed().as_nanos()).unwrap_or(i64::MAX)
}
```

```rust
/// A `Duration` as a `select` timeout, **never rounding a real wait down to
/// zero**.
///
/// `select` treats an all-zero `timeval` as "poll and return at once", so a
/// remaining duration under one microsecond would truncate to zero and the
/// drive loop would spin until the deadline passed. Any non-zero duration
/// therefore becomes at least one microsecond.
///
/// This is not a workaround for the platform: `sleep` promises to suspend for
/// *at least* the requested time, so rounding up honours the contract and
/// truncating down breaks it. Exactly zero stays zero, because then the
/// deadline really has passed.
fn select_timeout(d: std::time::Duration) -> libc::timeval {
    let micros = d.as_micros();
    let micros = if micros == 0 && !d.is_zero() { 1 } else { micros };
    libc::timeval {
        tv_sec: i64::try_from(micros / 1_000_000).unwrap_or(i64::MAX) as libc::time_t,
        tv_usec: (micros % 1_000_000) as libc::suseconds_t,
    }
}
```

Then replace the inline `libc::timeval { … }` construction near lines 328–334 with a call to `select_timeout`, keeping the existing `tv_ptr` null-versus-pointer handling for `None` exactly as it is — a `None` deadline must still pass a null pointer so `select` blocks indefinitely.

- [ ] **Step 4: Write `std/time/lib.nova`**

```nova
module std.time

// A point on this process's monotonic clock.
//
// Opaque: `nanos` is private, so a program obtains an `Instant` only from
// `now()` and compares two only through `duration_since` or `elapsed`. Held
// as nanoseconds since the runtime's single process epoch, so a reading is
// never negative and two `Instant`s are ordered by subtraction.
pub record Instant { nanos: Int }

// A span of time, opaque for the same reason and held in nanoseconds.
//
// Nanoseconds rather than a coarser unit because all three constructors below
// are then exactly representable, and because `elapsed` is a measurement whose
// precision a coarser unit would discard.
pub record Duration { nanos: Int }

const NANOS_PER_SEC: Int = 1_000_000_000
const NANOS_PER_MILLI: Int = 1_000_000
const NANOS_PER_MICRO: Int = 1_000

// The largest argument each constructor can scale without overflowing an
// `Int` of nanoseconds, and the clamped result for anything larger.
//
// These exist because **Nova's `Int` wraps** -- measured:
// `9223372036854775807 + 1` is `-9223372036854775808`. A wrapped duration can
// be negative, and `sleep` treats a non-positive duration as an immediate
// wake, so an unclamped `from_secs` would turn "sleep for ages" into "do not
// sleep at all", silently. Clamping yields a saturated answer instead of a
// wrong one -- the no-panic analogue of Rust's `Duration::from_secs`, which
// panics on the same overflow.
const MAX_SECS: Int = 9_223_372_036
const MAX_MILLIS: Int = 9_223_372_036_854
const MAX_MICROS: Int = 9_223_372_036_854_775
const MAX_NANOS: Int = 9_223_372_036_854_775_807

impl Instant {
    // The current reading of the monotonic clock.
    pub fn now() -> Instant {
        Instant { nanos: time_now_nanos() }
    }

    // How long since `self`. Zero if `self` is somehow in the future.
    pub fn elapsed(self) -> Duration {
        Instant::now().duration_since(self)
    }

    // The span from `earlier` to `self`, **saturating at zero** so an elapsed
    // time can never come back negative when the arguments are the wrong way
    // round.
    pub fn duration_since(self, earlier: Instant) -> Duration {
        if self.nanos <= earlier.nanos {
            Duration { nanos: 0 }
        } else {
            Duration { nanos: self.nanos - earlier.nanos }
        }
    }
}

impl Duration {
    // Whole seconds. Clamps above `MAX_SECS`; see the constants above.
    pub fn from_secs(s: Int) -> Duration {
        if s > MAX_SECS {
            Duration { nanos: MAX_NANOS }
        } else {
            Duration { nanos: s * NANOS_PER_SEC }
        }
    }

    // Whole milliseconds. Clamps above `MAX_MILLIS`.
    pub fn from_millis(ms: Int) -> Duration {
        if ms > MAX_MILLIS {
            Duration { nanos: MAX_NANOS }
        } else {
            Duration { nanos: ms * NANOS_PER_MILLI }
        }
    }

    // Whole microseconds. Clamps above `MAX_MICROS`.
    pub fn from_micros(us: Int) -> Duration {
        if us > MAX_MICROS {
            Duration { nanos: MAX_NANOS }
        } else {
            Duration { nanos: us * NANOS_PER_MICRO }
        }
    }

    // Whole seconds, truncating. `from_millis(1500).as_secs()` is `1`.
    pub fn as_secs(self) -> Int {
        self.nanos / NANOS_PER_SEC
    }

    // Whole milliseconds, truncating. `from_micros(1).as_millis()` is `0`,
    // which `tests/runtime/time_conversions.nova` pins deliberately.
    pub fn as_millis(self) -> Int {
        self.nanos / NANOS_PER_MILLI
    }
}
```

```rust

    /// not merely the presence of some deadline.
    ///
    /// `before` is captured **outside** the poll on purpose. The staged
    /// deadline is computed at or after `before`, so by monotonicity the
    /// difference is at least the requested 50ms however long this thread is
    /// descheduled; measuring from after the poll could drift below any lower
    /// bound and flake. The window is loose against jitter and tight against
    /// unit errors: a millionfold overshoot stages ~50,000 seconds and fails
    /// the upper bound, a millionfold undershoot stages ~50ns and fails the
    /// lower one.
    #[test]
    fn a_sleep_stages_a_deadline_of_the_right_magnitude() {
        let before = Instant::now();
        let fut = nova_rt_task_sleep_future_nanos(50 * 1_000_000);
        // SAFETY: `fut` is this call's own `FUTURE_SIZE`-byte block, so word 0
        // is its poll function -- exactly how
        // `the_sleep_futures_layout_is_the_one_the_abi_declares` reads it.
        let poll_addr = unsafe { (fut as *mut usize).add(FUTURE_SLOT_POLL).read() };
        // SAFETY: that word is a `PollFn` bit pattern by `fut`'s own
        // construction; a fn pointer and a `usize` are both pointer-width.

        let state = state_of(fut) as *mut u8;

        // `stage_park` aborts outside a task context, so borrow one for this
        // single manual poll and put back whatever was there.
        let previous = current_task();
        set_current_for_test(Some(0));
        // SAFETY: `poll`/`state` are the pair inside `fut`; `task_ctx` is
        // always null, matching every other call site in this crate.
        let first = unsafe { poll(state, std::ptr::null_mut()) };

        set_current_for_test(previous);

        assert_eq!(first, POLL_PENDING, "a sleep must park on its first poll");

        assert!(
            delta >= Duration::from_millis(40) && delta <= Duration::from_millis(500),
            "a 50ms sleep staged a deadline {delta:?} out -- a unit error, not jitter"
        );
```

```nova
// Suspend the current task for at least `d`.
//
// Parks rather than spins: this registers a deadline with the executor and is
// not polled again until that deadline passes, so a sleeping task costs no
// polls at all. Contrast `std/task`'s `yield_now`, which is re-queued
// immediately and deliberately.
//

// millisecond. Rounding up is what makes "at least" true; rounding down would
// also spin. A non-positive `d` wakes immediately rather than being rejected.
pub async fn sleep(d: Duration) {
    task_sleep_future_nanos(d.nanos).await
}
```
