# Phase 4.1, "The language on WASM", Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a WASM build runs async code, sleeps and timeouts, logs, and uses
`Mutex` and channels, with output identical to the native build's, and
reclaims memory between turns. WASM's std gains task, sync, time and log,
and a name from a module it lacks is E0092, naming the module. The
executor is a port of `nova-runtime`'s, in Nova, in `std/rt`; `async fn
main` returns to JS, which calls `nova_turn` on each timer; `block_on`
works, waiting for a deadline by reading the clock. The allocator is
`gc/pages.rs`'s page design, and a conservative mark-sweep collector runs
at the end of each turn. The gate: 94 of `tests/runtime/`'s 134 programs,
and `examples/03-producer-consumer`, behave under Node as natively, on all
three systems; the 40 left out are listed with their reasons.

**Architecture:**
- **`nova-resolver`:** `WASM_STD_MODULES` gains `$std.task`, `$std.sync`,
  `$std.time` and `$std.log`, in native's order; `Definitions` knows the
  target and maps each public name of a std module the target lacks to
  that module (`missing_module`); two more `Builtin::WASM_ONLY`,
  `future_poll` and `host_abort`.
- **`nova-typeck`:** E0092 at each place a name does not resolve; the two
  builtins' signatures.
- **`nova-mir`:** `RtFunc::on_wasm()` routes the task, time and log
  functions; `WasmRuntime::Builtin`, the yield future; `MemOp::Poll` and
  `MemOp::Abort`; `Module::runtime_exports`; mono roots `rt_alloc_leaf`,
  and for an `async fn main` `rt_task_main`, `rt_turn` and
  `rt_gc_switches`, and its shim calls `rt_task_main` on WASM.
- **`nova-codegen-wasm`:** `DATA_BASE` 128; the yield future's builder and
  poll function; `future_poll` as `call_indirect`; the `abort` import; the
  exports `nova_alloc_leaf`, `nova_turn` and `nova_gc_switches`; the shim's
  clocks, turn loop and collector switches.
- **`std/rt`:** the page allocator, leaf objects, the log configuration,
  the executor, the event loop's entry and turn, and the collector.
- **Records:** ADR 0040, and dated notes.

## Conventions

- **Scratch directory:** `$P` is the session's scratch directory, outside
  the repository. Set it in every shell before a command that names `$P`.
- **The ledger:** `$P/ledger-41x.md`. Every ruling made while executing goes
  there, with its cost if wrong; so do each task's figures.
- **Commits.** Each task's message is written to `$P/msg-41-<task>.txt`:
  the subject the task names, a blank line, and the session's attribution
  lines. Then `git add -A`; `git status --short` lists only the task's
  files; and `git commit -F "$P/msg-41-<task>.txt"`.
- **The baseline's full output** is `$P/base-41.txt` (Task 0).
- **Runs.** Cargo runs with `CARGO_INCREMENTAL=0`, and `W` stands for
  `NOVA_REQUIRE_NODE=1 cargo test -p nova-cli --test wasm_tests`.
- **The patches.** Each task's code is in patch blocks below, each marked
  `<!-- patch NAME -->` and fenced with four backticks. They are the
  prototype's commits, so apply them; do not retype them. From the
  repository's root:

  ```sh
  PLAN=docs/superpowers/plans/2026-10-15-phase-4-1-the-language-on-wasm.md   # this file, committed
  block() {
    awk -v name="$1" '
      $0 == "<!-- patch " name " -->" { grab = 1; next }
      grab && /^````diff$/ { inside = 1; next }
      inside && /^````$/ { exit }
      inside { print }
    ' "$PLAN" > "$P/$1.patch"
  }
  patch_block() {
    block "$1" && git apply --check "$P/$1.patch" && git apply "$P/$1.patch"
  }
  ```

  `patch_block t1-tests` applies the block named `t1-tests`. A block that
  does not apply means the tree differs from the plan's: stop, and record
  why in the ledger.
- **Generated files are generated, not patched:** each `tests/wasm/*.stdout`,
  by `nova run` natively; its SHA-256 is given.
- **Each task** is test first: its tests' patch, their run and the expected
  failure, then its code's patch, its run and the expected pass. Unit tests
  in the files a task changes ride in its code's patch, and Task 9's
  mutants show they bite. Each task then runs its checks:
  - `cargo fmt --all -- --check`;
  - the workspace's clippy, `cargo clippy --locked --all-targets
    --all-features -- -D warnings`, as CI runs it;
  - `cargo run --locked -q -p nova-cli -- fmt --check std examples
    tests/wasm`, when it changes a `.nova` file.

  It ends with one commit. A difference from an `Expected:` is fixed in
  the smallest way and recorded in the ledger as a ruling, with its cost if
  wrong.

## Decisions: where this plan settles what the spec leaves open

Each was a ruling while prototyping; each is open to the user's review.
Decisions 2, 4, 7, 12, 13, 16, 19 and 22 differ from a sentence of the
approved spec, decision 26 from a count, and decision 30 from its list of
crates.

1. **E0092's map holds every public name of each std module the target
   lacks,** in all three namespaces. The resolver parses each such module
   and runs its own `collect_item` over it, into scopes it then drops. The
   type checker consults the map at the nine places a name can fail to
   resolve: a type, a value, a call, a qualified path (which was E0900), a
   record literal, and four places a trait is named. E0092 is labelled on
   the name, "not on target wasm", and takes the place of E0001 and its
   fixes.
2. **The log configuration is two state words:** 32 is 0 while unset, else
   1 plus whether lines go to stderr; 40 is the level, as given. Spec §4.6
   stores the flag as 0 or 1; a word of 0 must also mean "unset", which
   reads as native's default. The getter still answers 0 or 1.
3. **The state words, as assigned:** 8 the allocator's metadata (4.0's
   `HEAP_NEXT`), 16 and 24 the hash seed, 32 and 40 the log configuration,
   48 the executor's block, 56 the bytes allocated since the last
   collection, 64 the next threshold, 72 the collections so far, 80 the
   collector's switches. 88 to 120 are free.
4. **The allocator's metadata is three WASM pages,** from the first 64 KiB
   boundary at or above `heap_base()`: the first heap page's number, the
   frontier, the worklist, three words per size class, and a page table of
   16,384 words, one per page of the largest memory. The table is indexed
   by an address's page number, `address >> 16`, where spec §6.2 writes
   `(address - heap base) >> 16`: the same table, from page 0.
5. **A small page's record is in the page:** a 1,568-byte header holds the
   class, the slot size, the slot count, the next page of the class with a
   free slot, and the three 64-word bitmaps. A page so holds a few slots
   fewer than native's: 3,998 of 16 bytes, where native's holds 4,096.
   Native keeps the record out of band; WASM has no system allocator to
   keep it in.
6. **A large object's size and flags are in front of it, in its first
   page,** 16 bytes, found through the page table and never through the
   object, so nothing in a string's bytes can pass for them.
7. **Every empty page is free for any later use, with no reserve:** spec
   §6.2's reserve of 16 pages means nothing when no page is ever given
   back, and the spec's pages "beyond the reserve" are free for any class.
8. **An allocation over 1 GB panics with "out of memory"** before any page
   arithmetic, and so does one the memory cannot grow for.
9. **`nova_alloc` stays, and `nova_alloc_leaf` joins it** for the shim's
   strings. Both are roots of every WASM build: `rt_alloc` as 4.0 made it,
   `rt_alloc_leaf` through mono's `RT_EXPORTS`.
10. **The yield future is `WasmRuntime::Builtin`, a fourth kind.** The
    backend emits two functions after MIR's: a builder, `() -> future`, and
    a poll function, in the table. A `task_yield_future()` call calls the
    builder.
11. **`future_poll` and `host_abort` are `Builtin::WASM_ONLY`,** lowered to
    `MemOp::Poll`, a `call_indirect` through the future's table index with
    its state and a null context, and `MemOp::Abort`, a call of the shim's
    `abort`, imported as `env.abort`. A module that polls has a table, if
    an empty one.
12. **The leaf futures are the routed functions themselves:**
    `rt_task_sleep_future_nanos`, `rt_task_join_future` and
    `rt_task_timeout_future` are `async fn`s, so each fixes its deadline
    or its target at its first poll, where spec §4.1 and §4.3 fix it when
    the future is built. std awaits each where it builds it, so the first
    poll follows at once, in the same poll of the same task, and nothing
    runs between. It spares a builtin to turn a future into an `Int`.
13. **The map from a state to its task is a hash index,** where spec §4.2
    says a scan of the task table: a scan costs a pass over every task at
    each join. The index is filled again from the task table on growth,
    and after each collection without the tasks whose states were freed.
14. **The executor's tables are leaf objects,** grown by doubling, which
    the block's words point at; the collector marks the block and each
    table, and traces each unreleased task's state.
15. **`rt_task_is_done` and `rt_task_take_output` are written, though
    nothing reaches them:** no std code calls `task_is_done`, and no MIR
    emits `TaskTakeOutput`. Every WASM build type-checks them, and their
    messages are native's.
16. **The message for two tasks staged in one poll** writes a deadline as
    `Some(_)`, where native writes an `Instant`'s fields, and spec §4.1
    asks for native's message. No well-formed program reaches it, and an
    `Instant`'s fields cannot be reproduced.
17. **Task 4 runs `async fn main` through `block_on`,** by rooting
    `rt_task_block_on`, so each task's commit runs every async program;
    Task 5 moves `async fn main` to the event loop.
18. **After `main`, the shim calls `nova_turn` at once** to learn the first
    delay. `main`'s own turn collects at its end, in `rt_task_main`.
19. **Only a module with an `async fn main` exports `nova_turn` and
    `nova_gc_switches`,** where spec §5 says "only programs that use the
    executor": a synchronous `main` that calls `block_on` has run every
    task when that call returns, and needs no turn. Such a program never
    collects: its one turn ends the program, where spec §6.5 collects
    "after `main` returns". So `NOVA_GC_STRESS` and `NOVA_GC_DEBUG` (spec
    §6.6) change nothing in it on WASM, where natively they do.
20. **The collector's switches are one export, `nova_gc_switches(flags)`,**
    1 stress and 2 debug, set before `main`. `init`'s `gcStress` and
    `gcDebug` override Node's environment.
21. **The worklist is pages of the collector's own,** kind 5 in the page
    table, doubled when full and kept between collections.
22. **The gate is 94 programs, where spec §9.2 lists 43 to add:** 4.0's
    46, the 43, and five that 4.0's build already ran but its gate left
    out: `bytes_api`, `eprint_family`, `hash`, `hash_diffusion` and
    `json_traits`. Spec §1's 94 counts them.
23. **The lists are checked twice:** every program is in the gate or left
    out, and each one left out is refused by `check --target wasm` for its
    reason, E0092 naming exactly its modules, or its error.
24. **E0091 can no longer be reached through WASM's std:** every runtime
    function it reaches is routed, the shim's or the backend's.
    `lower_tests.rs` shows E0091 still works by taking `rt_int_to_str`
    away, and `wasm_tests.rs`'s E0091 test becomes "an `async fn main`
    runs".
25. **The clocks' test is a unit test in `shim.rs`,** run under Node, as
    4.0's parser test is.
26. **The stress runs are a module of their own, `mod stress`:** the 19
    async programs and the 13 that `run_tests.rs` runs under
    `NOVA_GC_STRESS` (`bytes_api` from Task 7, which gates it), where spec
    §9.3 counts the 8 of those 4.0's gate held.
27. **Three collector programs more than spec §9.3 names:**
    - `gc_yields_after_collections`, for the zeroing of reused slots;
    - `gc_keeps_many`, for a large object and the worklist's growth;
    - `gc_forgets_freed_states`, for the index's pruning:
      `recycled_task_state`'s `main` is not async, so on WASM it never
      collects.
28. **Hello world grows to about 4.4 KB gzipped,** from 4.0's 2.1 KB
    (each file by `gzip -9`): the page allocator. The limit stays 30 KB.
29. **Names the spec gives otherwise:** the builtin is `host_abort`, for
    spec §4.5's "host function `abort`", which is its import's name; and
    the functions JS calls are `rt_turn` and `rt_gc_switches`, exported as
    `nova_turn` and `nova_gc_switches`.
30. **`nova-driver` does not change,** where spec §8 lists it: its runtime
    table already takes every `$std.rt` function by name, and a target's std
    modules are the resolver's list.

+    if id < 0 { panic("${who}: this future was never spawned, so there is no task to ask about") }

+fn take_output(e: Int, id: Int) -> Int {
+    if id < 0 || id >= mem_load64(e + 8) { panic("nova_rt_task_take_output: unknown task id") }

+        panic(
+            "nova_rt_task_take_output: task ${id} has not completed; poll nova_rt_task_is_done until it reports true first",
+        )
+    }

+        panic(
+            "nova_rt_task_take_output: task ${id}'s output was already taken; taking released the state object's GC root, so a heap-valued output may already have been collected",

+// are parked, none has a deadline, and nothing is queued.
+fn report_deadlock(e: Int) {

+    let mut plural = "tasks are"

+        } else if mem_load64(p + 16) != 0 {
+            eprint("  task ${id} is waiting for task ${target1 - 1} to finish, with a deadline\n")
+        } else {
+            eprint("  task ${id} is waiting for task ${target1 - 1} to finish\n")

+fn rt_task_spawn(fut: Int) -> Int { spawn_task(exec(), fut, false) }

+// `nova_rt_task_block_on` (spec 4.1 §4.4): the root queued behind earlier
+// spawns, every task drained, and the root's output. With only deadlines
+// left, it waits for the earliest by reading the clock in a loop, as native
+// `thread::sleep` holds the thread.
+fn rt_task_block_on(fut: Int) -> Int {
+    let e = exec()
+    if mem_load64(e + 112) != 0 {
+        panic(
+            "nova_rt_task_block_on called re-entrantly: an async fn must not call block_on, which would run a second executor loop from inside the first one's frame",
+        )
+    }
+    mem_store64(e + 112, 1)
+    let root = spawn_task(e, fut, true)
+    drain(e)
+    while mem_load64(e + 64) > 0 {
+        let at = earliest(e)
+        if at < 0 { report_deadlock(e) }
+        while time_now_nanos() < at {}
+        wake(e, 0 - 1, time_now_nanos())
+        drain(e)
+    }
+    mem_store64(e + 112, 0)

+fn rt_task_is_done(fut: Int) -> Bool {

+    done != 0
+}
+
+// `nova_rt_task_take_output`.
+fn rt_task_take_output(id: Int) -> Int { take_output(exec(), id) }
+
+// `nova_rt_task_release`: idempotent.
+fn rt_task_release(fut: Int) {
+    let e = exec()

+}
+
+// A deadline `nanos` from now, a negative count as 0, saturating
+// (`deadline_nanos_from_now`).
+fn deadline_from_now(nanos: Int) -> Int {
+    let now = time_now_nanos()
+    let mut d = nanos
+    if d < 0 { d = 0 }
+    if d > 9223372036854775807 - now { 9223372036854775807 } else { now + d }
+}
+
+// The leaf futures (spec 4.1 §4.3) are `async fn`s over the one the backend
+// builds, `task_yield_future`, which is pending once with no wait staged.
+// Each stages its wait, then awaits a fresh one, so its task parks; woken, it
+// checks again. Each fixes its deadline or its target at its first poll,
+// which comes as it is built: std awaits each where it builds it.
+
+// `nova_rt_task_sleep_future_nanos`: due at once completes without
+// suspending.
+async fn rt_task_sleep_future_nanos(nanos: Int) -> Int {
+    let deadline = deadline_from_now(nanos)
+    while time_now_nanos() < deadline {
+        stage_deadline(exec(), deadline)
+        task_yield_future().await
+    }
+    0
+}
+
+// `nova_rt_task_join_future`: an unspawned future aborts.
+async fn rt_task_join_future(fut: Int) -> Int {
+    let e = exec()
+    let target = task_id_of(e, fut, "nova_rt_task_join_future")
+    while (task_flags(e, target) & 1) == 0 {
+        stage_task(e, target)
+        task_yield_future().await
+    }
+    0
+}
+
+// `nova_rt_task_timeout_future`: 0 when the future at `inner` completes,
+// polled first, and 1 when the deadline passes first. A wait the inner
+// future staged is dropped when the timeout completes, and the inner future
+// is abandoned, not cancelled.
+async fn rt_task_timeout_future(nanos: Int, inner: Int) -> Int {
+    let deadline = deadline_from_now(nanos)
+    let e = exec()
+    while true {
+        let staged = mem_load64(e + 88)
+        let at = mem_load64(e + 96)
+        let target = mem_load64(e + 104)
+        let status = future_poll(inner)
+        if status != 0 && status != 1 {
+            panic(
+                "nova_rt: a future polled by a timeout returned ${status}, which is neither POLL_PENDING (0) nor POLL_READY (1)",
+            )
+        }
+        let mut done = 0 - 1
+        if status == 1 { done = 0 } else if time_now_nanos() >= deadline { done = 1 }
+        if done >= 0 {
+            mem_store64(e + 88, staged)
+            mem_store64(e + 96, at)
+            mem_store64(e + 104, target)
+            return done
+        }
+        stage_deadline(e, deadline)
+        task_yield_future().await
+    }
+    0
+}

+            let mut kept = 0
+            let mut k = 0
+            while 64 * k < n {
+                let a = mem_load64(base + 32 + 8 * k)
+                let marks = mem_load64(base + 544 + 8 * k)
+                freed = freed + popcount(a ^ marks) * slot
+                kept = kept + popcount(marks)
+                mem_store64(base + 32 + 8 * k, marks)
+                mem_store64(base + 544 + 8 * k, 0)
+                k = k + 1
+            }
+            live = live + kept
+            bytes = bytes + kept * slot
+            if kept == 0 {
+                set_page_word(m, p, 1)
+            } else if kept < n {
+                let cls = word >> 8
+                mem_store64(base + 24, mem_load64(m + 448 + 8 * cls))
+                mem_store64(m + 448 + 8 * cls, p)
+            }
+        } else if kind == 3 {
+            step = word >> 8
+            let size = mem_load64(base)
+            let flags = mem_load64(base + 8)
+            if (flags & 1) != 0 {
+                mem_store64(base + 8, flags - 1)
+                live = live + 1
+                bytes = bytes + size
+            } else {
+                freed = freed + size
+                let mut k = 0
+                while k < step {
+                    set_page_word(m, p + k, 1)
+                    k = k + 1
+                }
+            }
+        }
+        p = p + step
+    }
+    c = 0
+    while c < 24 {
+        let next = mem_load64(m + 448 + 8 * c)
+        if next != 0 { mem_store64(m + 448 + 8 * c, mem_load64(next * PAGE + 24)) }
+        mem_store64(m + 64 + 8 * c, next)
+        mem_store64(m + 256 + 8 * c, 0)
+        c = c + 1
+    }
+    mem_store64(m + 40, freed)
+    mem_store64(m + 48, live)
+    mem_store64(m + 56, bytes)
+}
+
+// Whether an allocated object starts at `a`: after a sweep, whether `a`
+// still names one (`slot_scan`, and the large objects' search).
+fn gc_is_live(m: Int, a: Int) -> Bool {
+    if a < mem_load64(m) * PAGE || a >= mem_load64(m + 8) * PAGE { return false }
+    let p = a / PAGE
+    let base = p * PAGE
+    let kind = page_word(m, p) & 255
+    if kind == 2 {
+        let off = a - base - SLOTS
+        let slot = mem_load64(base + 8)
+        if off < 0 || off % slot != 0 || off / slot >= mem_load64(base + 16) { return false }
+        let i = off / slot
+        let bits = mem_load64(base + 32 + 8 * (i >> 6))
+        return ((bits >> (i & 63)) & 1) != 0
+    }
+    kind == 3 && a == base + 16
+}
+
+// Forget every freed state (`prune_freed_states`): a task whose state was
+// freed is marked so, and the index filled again without it, so a new
+// object at the same address names no old task.
+fn gc_prune(m: Int, e: Int) {
+    let n = mem_load64(e + 8)
+    let mut id = 0
+    while id < n {
+        let flags = task_flags(e, id)
+        if (flags & 8) == 0 && !gc_is_live(m, mem_load64(task_at(e, id) + 8)) {
+            set_task_flags(e, id, flags | 8)
+        }
+        id = id + 1
+    }
+    index_fill(e)
+}

+# ADR 0040 — The WASM collector and executor
+
+## Status
+
+Accepted, 2026-10-15 (Phase 4.1, branch `claude/loving-archimedes-frtf5q`;
+spec `docs/superpowers/specs/2026-10-15-phase-4-1-the-language-on-wasm-design.md`).
+The executor's language, the collector's timing and `block_on` on WASM are
+the user's decisions of 2026-10-15.
+
+## Context
+
+ADR 0039 gave a WASM build its runtime, `std/rt`, written in Nova, with an
+allocator that only grew, and no async: `async fn main` was E0091.
+- `nova-spec/13-RUNTIME.md` §8 says a WASM build starts with reference
+  counting. `docs/phase-4-plan.md` §3 decision 3 chose mark-sweep between
+  event turns instead: the graph of signals and effects is full of cycles.
+- The same plan's decision 4 put async on the browser's event loop, with
+  no `block_on` on WASM.
+- `nova-runtime`'s executor (`task.rs`) and collector (`gc.rs`,
+  `gc/pages.rs`) cannot run in a browser: the collector scans the native
+  stack, and the executor blocks the thread to wait.
+
+## Decision
+
+1. **The collector is conservative, non-moving mark-sweep, run only
+   between turns.**
+   - A turn is one call from JS that runs Nova code: `main`, or
+     `nova_turn`. When it returns, the WASM stack holds nothing the
+     collector must see, so there is no stack to scan, and no shadow stack.
+   - Its roots are the executor's block and tables, and each unreleased
+     task's state, as `nova-runtime` pins it. 4.2's table of values JS
+     holds will be one more.
+   - A word is a pointer if it falls inside an allocated object. Strings,
+     `Bytes` and the executor's tables are leaves, kept but not traced.
+     Marking uses a worklist in memory: V8's stack is about 1 MB.
+   - The threshold is native's: a collection once the bytes allocated since
+     the last reach 1 MiB, then twice the live bytes. `NOVA_GC_STRESS`
+     collects at the end of every turn, and `NOVA_GC_DEBUG` writes native's
+     line. JS passes them in, from Node's environment or `init`'s options.
+   - Only a program with an `async fn main` has turns after `main`, so only
+     it collects, and only its module exports the switches.
+   - A long computation within one turn does not collect: it stops with
+     "out of memory" at the memory's 1 GB.
+2. **The allocator is `gc/pages.rs`'s design.** Objects of 2,048 bytes or
+   less take a slot of one of 24 size classes in a 64 KiB page, which is
+   WASM's page; larger ones a run of pages. Three bitmaps per page record
+   which slots are allocated, marked and to be traced, and a page table
+   finds a page's kind. A large object's size and flags are in front of it
+   in its first page, where native keeps them out of band: WASM has no
+   system allocator to hold them. The page table, not the object, finds
+   them, so nothing in a string's bytes can pass for them. Slots are zeroed
+   when handed out. Memory cannot shrink, so an empty page is free for any
+   later use.
+3. **The executor is written in Nova, in `std/rt`,** a port of `task.rs`
+   with its order: spawn order, a FIFO queue, timers woken in the order
+   they were parked, the deadlock report.
+   - The backend builds one future itself, the yield future, pending once
+     with no wait staged. `sleep`, `join` and `timeout` are `async fn`s
+     over it, which stage their wait and await a fresh one; each fixes its
+     deadline or target at its first poll, which comes as std builds it.
+   - A WASM-only builtin, `future_poll`, polls a future once; the executor
+     drives every task through it. Another, `host_abort`, ends the program
+     after the deadlock report, which has no `nova: panic:` prefix.
+   - Its state is in leaf objects that a state word points at. A state's
+     task is found through a hash index, pruned after each collection, so a
+     reused address names no old task.
+4. **`async fn main` runs on the event loop.** Its shim spawns the root and
+   runs what can run, then returns to JS. Each `nova_turn` wakes what is
+   due, runs the queue, collects if due, and returns the milliseconds to
+   the next deadline, or -1 when no task waits; JS sets a timer for it. A
+   module exports `nova_turn` only when it has an `async fn main`.
+5. **`block_on` works on WASM,** unlike the phase plan's decision 4, by
+   the user's decision: it runs the executor within the call, and waits for
+   a deadline by reading the clock in a loop. A page that sleeps inside
+   `block_on` does not respond until it returns; `async fn main` is the
+   event loop's way.
+6. **`std/rt`'s state words grow to `8..128`,** and the data segment starts
+   at 128: the allocator's metadata, the executor's block, the log
+   configuration and the collector's words have fixed addresses, which
+   need no root.
+
+## Consequences
+
+- **Two executors and two collectors exist,** Rust's and Nova's. The
+  gate's 94 programs, run both ways and under stress, keep their order and
+  their results equal.
+- **WASM's std gains task, sync, time and log.** A name from a module it
+  lacks is E0092, naming the module; E0091 is unreachable through WASM's
+  std.
+- **Async code that waits in `block_on` blocks a page,** as it blocks a
